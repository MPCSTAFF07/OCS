# OBS Caster Share v0.2 / GitHub Pages対応版

実況解説は招待URLをChrome / Edgeで開くだけで、本番映像と共有用音声を視聴できます。
実況解説のPCにPython・OBS・Tailscaleを入れる必要はありません。
配信PCはOBSのLuaスクリプト＋カスタムブラウザドック＋Python中継ソフトで動作します。

## 今回の変更

- 視聴ページをGitHub Pagesのリポジトリ配下で公開できます。
- 配信PCは公開サーバーに外向き接続するので、配信PCのポート開放やVPNは不要です。
- 公開サーバーに接続受付用ソフトとcoturnを置きます。
- ブラウザ側はTURN中継を使用します。配信PC側のTURN接続はTCPを使います。
- OBS内から開始・停止、招待URLコピー・更新、接続者確認と切断を行います。
- 本配信・録画と別の出力です。OBSの配信遅延設定を待たず、現在の本番画面を送ります。
- 通信とエンコードの遅延はあります。完全な同時表示・実況者間のフレーム同期は保証しません。

## 先に必要なもの（配信者のみ）

1. Windowsの配信PC、OBS、Python 3.12 64-bit（3.11 / 3.13も検出可能）。
2. 新しいGitHubリポジトリ。
3. Ubuntuの公開サーバー。既存AWS EC2を使えますが、通信帯域・通信料金・負荷の確認が必要です。
4. そのサーバーで既にHTTPSが使えるドメインとNginx設定。
5. AWSセキュリティグループを変更できる権限。

GitHub Pagesだけでは映像を中継できません。AWS側の導入が完了するまでは視聴できません。
このZIPには配信キーやサーバー認証情報を含めていません。

## 1. GitHub Pagesを準備

1. GitHubで公開リポジトリを作ります。名前の例：`obs-caster-share`。
2. このフォルダの中身をアップロードします。実行後のruntimeフォルダや仮想環境はアップロードしません。
3. Settings → Pages → Deploy from a branch → main /docs → Save。
4. 表示されたURLを控えます。例：`https://ユーザー名.github.io/obs-caster-share/`。

視聴ページのファイルはdocsの中です。リポジトリ直下のindex.htmlではありません。
GitHub側の設定後に公開されます。このZIPを展開しただけでは公開されません。

## 2. 公開サーバーに導入

ZIPをEC2のホームディレクトリにアップロードして展開します。
既にHTTPSが動いているドメインに、`/caster/`の接続経路を追加します。
インストーラーは既存のNginx内から対象ドメインのHTTPSブロックを探し、追加前にバックアップして構文検証します。
別システムの設定ファイルや既存のcoturn設定は上書きせず、このツール用の設定・サービスを追加します。

展開したフォルダへ移動して、以下の値を自分のものに置き換えます。

```bash
sudo python3 deploy/install.py \
  --domain 配信サーバーのドメイン \
  --public-ip EC2のパブリックIPv4 \
  --pages-url https://ユーザー名.github.io/obs-caster-share/
```

ドメインはhttps://を付けず入力します。既存のHTTPS証明書が使われ、新しい証明書取得はしません。
EC2のプライベートIPv4は自動検出します。必要なら `--private-ip 172.31.x.x` を指定できます。
対象のNginx設定が自動で見つからない場合は `--nginx-site /etc/nginx/sites-available/対象ファイル` を追加します。
Nginxのバックアップは `/etc/obs-caster-share/nginx-site-before-caster.conf` に保存します。

AWSセキュリティグループと、使用している場合はホスト側ファイアウォールで次を許可します。

| プロトコル | ポート | 用途 |
| --- | --- | --- |
| TCP | 443 | HTTPS / 配信PCの接続 |
| TCP / UDP | 3479 | TURN中継への接続 |
| UDP | 48900〜49000 | TURN中継用の映像・音声 |

遠隔の一般回線から使うため、これらのポートは利用者の接続元から到達可能にします。
SSHなど既存のポートのルールは維持してください。
企業・学校などが3479番への通信も禁止している場合は、この版では接続できないことがあります。

導入後：

```bash
sudo systemctl status obs-caster-relay obs-caster-turn --no-pager
curl https://配信サーバーのドメイン/caster/health
sudo cat /root/obs-caster-connection.json
```

healthが `ok: true` なら接続受付は動作しています。映像経路の開通は、実際の遠隔接続で別途確認します。
接続設定にある `publisher_key` は配信者専用です。GitHubや実況解説へ渡さないでください。

## 3. 配信PCへ導入

1. ZIPをすべて展開し、固定の場所に置きます。例：`C:\Tools\obs-caster-share`。
2. Python 3.12がなければ、Python Install Manager利用時はPowerShellで `py install 3.12` を実行。
3. `INSTALL.cmd`を実行します。
4. `START.cmd`を実行します。黒いウィンドウは使用中閉じません。
5. OBS → ツール → スクリプト → ＋で `caster-share.lua` を追加します。
6. 自動で開いた管理画面に、サーバー導入時に発行された中継URL、GitHub Pagesの視聴URL、配信キーを入力して保存。
7. 「公開サーバー：接続済み」を確認します。
8. 「管理URLをコピー」し、OBS → ドック → カスタムブラウザドックへ追加します。

管理URLは再起動ごとに変わります。再起動した場合はOBSのドックURLも新しいものに更新してください。
この版では以前のSETUP_TAILSCALE.cmdやFIREWALL.cmdは使用しません。
以前の版と同時に起動せず、以前のLuaスクリプトもOBSから外してから新しいものを追加してください。

## 4. 音声を設定

OBSの音声ミキサー → オーディオの詳細プロパティで共有用トラック2を設定します。

| 音源 | 本配信用トラック | トラック2（実況共有） |
| --- | --- | --- |
| ゲーム音 | ON | ON |
| BGM・効果音 | ON | ON |
| Discordの実況解説の声 | ON | OFF |
| 配信者のマイク | 必要に応じてON | 通常OFF |

ゲームとDiscordが同じデスクトップ音声に入っている場合は、アプリケーション音声キャプチャなどで分けてから設定します。
ツールが声を自動除去するわけではありません。ゲーム音まで消さないよう確認してください。
共有トラック番号と画質はOBSのスクリプト設定で選び、共有を停止→再開して反映します。
標準画質は960×540、高画質は1280×720です。

## 5. 本番の使い方

1. 配信PCでSTART.cmdとOBSを起動し、ドックで「共有開始」。
2. 「共有中」と「公開サーバー：接続済み」を確認。
3. ドックの「URLをコピー」で招待URLを実況解説へ送る。
4. 実況解説はChrome / Edgeで開き、名前を入力して「視聴開始」。
5. 声はこれまで通りDiscordで通話。視聴ページはマイクもカメラも使いません。
6. 終了したらOBS内で「停止」。中継ソフトはCtrl+Cで終了。

最大6人。人数に応じて配信PCのCPU負荷と回線使用量が増えます。まず2人で検証してください。
招待URL更新で既存接続も切断し、古いURLを無効にします。
個別の「切断」ではURLは無効にならず、同じ人が再接続できます。
一度のWebRTC接続は12時間以内を目安にし、長時間運用では再接続して新しい中継認証を取得してください。

## 困ったとき

| 状態 | 確認 |
| --- | --- |
| Pythonが見つからない | Python 3.12 64-bitを追加。`py -3.12 --version` |
| 公開サーバーに接続できない | 中継URLと配信キー。サーバーのhealth、NginxのWebSocket経路 |
| 招待URLが無効 | 配信PC再起動後、またはURL更新後の新しい招待URLを渡す |
| ページだけ開いて映像が来ない | AWSのTCP/UDP3479、UDP48900〜49000、coturnのexternal-ip設定 |
| CORSエラー | サーバー導入時のpages-urlが実際のGitHub Pagesのオリジンと一致しているか |
| OBSの映像が来ない | Lua追加、OBSログのcaster-share-output、停止→開始 |
| 声が遅れて返る | 共有トラックからDiscord音声を除外 |
| CPU負荷が高い | 標準画質へ変更。視聴人数を減らす |

サーバーログ：

```bash
sudo journalctl -u obs-caster-relay -u obs-caster-turn -n 80 --no-pager
```

## 1080p / 最大60FPS・管理画面での音源選択

[設定と更新手順](AV_SETTINGS.md)を参照してください。ゲーム音など共有したいOBS音源だけを管理画面で選べます。既存の本配信・録画に使っていない音声トラックを共有用に確保します。60FPSにはOBS側も60FPSの設定が必要です。
